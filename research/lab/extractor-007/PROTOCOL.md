## Execution contract

Use the existing local endpoint and discovered model in `local-config.json`. Existing server code and a separately recorded live probe establish support for `response_format.json_schema`. Constrained generation governs syntax; the local binder still validates every output, and independent review checks meaning. No service installation or modification is required. No remote inference is allowed by this runner.

The model supplies semantic choices. Code supplies source identifiers, revisions, evidence paths, caller-owned comparison properties and derived unknown paths. Clock strings are converted to minutes in code. Generated full-source references mean input provenance, never a claim that the text entails every output field. Free text and wrong but well-typed interpretations remain visible to evaluation; gold cannot repair them.

Plain and structured preparations receive identical source content, semantic assignment and meaningful caller vocabulary. Only the structured condition receives serialization instructions and a schema. The plain condition explicitly requests prose and receives no competing schema. The five transformation fields are independently extracted from each text; the model-facing person field removes the ambiguous subject/object label.

The caller strips gold, checks, rubrics and future questions before adapter formatting/binding/operations. Model packets omit source state and pair verdicts. Preparation is question-blind except the explicitly task-aware compatibility and scheduling assignments. Test-only exact comparisons are computed after extraction and never influence requests, decoding or accepted output.

## Consumers and scores

The structured reader sees bound candidate meaning, unresolved fields and the actual operation result. Generated evidence envelopes containing full source text are excluded; the transformation field-inspection receipt also excludes those quotes. The prose reader sees only prepared prose. Both see the same question and minimal caller vocabulary. This is a readiness comparison, not an isolated causal test of mathematical contribution or a context-budget/repeated-use study.

Record separately: HTTP/model identity, syntax, full contract validity, exact critical field checks, source-grounded semantic fidelity, unsupported assertions, uncertainty, actual operation result, literal reader answer and support by the presented packet. A correct unknown answer after unavailable extraction does not count as retained memory. Preserve and report real errors even if the envelope is valid. Evidence-only failure counts from 006 are not directly comparable because source bookkeeping is now deterministic.

Independent review judges all outputs against the source and the literal question; required detail must be asked for. Every critical semantic error remains a failure. No exception is made to make the run pass. Disputed readings receive independent adjudication. A model's confidence or its generated provenance does not verify its own answer.

Readiness requires every structured output to be consumable, all critical source-derived field checks to pass, no critical semantic error, and all structured readers to satisfy the literal question without unsupported additions. Report development and confirmation separately. Report transformations as checks of named annotations; harmless rewrites may still require semantic review of free prose. No blanket meaning-preservation claim is allowed.
