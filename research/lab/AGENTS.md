# Laboratory execution contract

This laboratory evaluates optional supplements to Circadian. The working lifecycle is the baseline. Read the current result linked at the top of `README.md` before continuing; earlier protocols and outputs are historical evidence, not an instruction to restart an old run. All six original proposals remain in scope unless the operator changes it. Use general-purpose scenarios and the smallest useful implementation.

## Ownership

The assigned execution owner carries authorized work through implementation, appropriate code checks, a declared bounded run, independent source-grounded assessment and a written result. The operator is not the test runner or a relay for routine implementation decisions. Resolve missing details from actual files, existing configuration and endpoint discovery before asking. A research failure is a result to explain; an execution fault is a concrete problem to diagnose and repair. Finish independent work while a narrower issue is unresolved. **Enforcement: DOCTRINE, inspected in the final evidence review.**

## Controls and evidence

- Use the existing selected local service. Verify its actual model and serving capabilities; do not install a replacement service or add a provider to escape an interface defect. A supported response format is not evidence that it improves this task. **DOOR: the current runner's local endpoint and configuration checks.**
- Declare sources, model/settings, prompts, conditions, call ceiling, scoring and stop behavior before dispatch. Retain independent inspection and exact source/input hashes. Completed or uncertain attempts cannot be overwritten, resumed by deleting markers, or silently replaced. **DOOR: immutable preparation, hash verification, exclusive start marker and call accounting.**
- Keep future questions, gold and grading material out of question-blind preparation. Shared meaning instructions belong in both conditions; serialization instructions belong only in the structured condition. Caller-owned IDs and provenance belong in code. Provenance is not entailment. **Enforcement: boundary tests and independent instrument inspection.**
- Preserve raw requests/responses, model identity, time, usage and every failed output. Do not use gold to fix an interpretation or normalize an invalid output into a passing sample. Any permitted repair must be declared as a separate condition. **DOOR: retained receipts and strict binders; source-fidelity review checks the remaining DOCTRINE.**
- Separate syntax, contract validity, source meaning, operation correctness, requested answer completeness and support by the actual reader packet. An unavailable-memory refusal is not retained knowledge. Do not count repeated cases as fresh confirmation or historical controls as new samples. **Enforcement: separate assessment fields and independent source-grounded review.**
- Report the actual result for every addition, including limitations. A passing deterministic prototype is not measured model benefit; a completed run is not a passed readiness requirement. Preserve failures rather than continuously tuning until a score turns green. **Enforcement: raw evidence, versioned reports and independent final inspection.**

## Circadian boundary

Keep changes under research until production integration is explicitly in scope. An eventual optional addition must preserve the ordinary Circadian path when it is disabled or its input is rejected. The lab's unavailable-memory marker is a measurement device, not a policy to discard working baseline memory. No new package, database or standing service is required by this contract. **Enforcement: DOCTRINE plus changed-path inspection; production integration requires its own concrete acceptance checks.**
