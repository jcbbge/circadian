# Six augmentation designs: verified implementation seams

Read-only source curation, 2026-10-10. Circadian is the working foundation. These are design seams, not an audit or permission to change production. Paths below are relative to `/Users/jrg/circadian` and all were read during this assignment.

## Reading and rendering

- **Scope is presently a location/slug partition, not an arbitrary semantic query.** `resolveScope` matches cwd/project identity against a TSV registry or accepts a validated override (`src/scopes.ts:36`). `scopedView` reads the scope's NOW, scoped episodes and atoms whose quoted episode has that scope (`src/scopes.ts:76`, `src/scopes.ts:106`). Applicability in proposal 2 therefore cannot be equated with current scope/origin.
- **Budgets are estimated, not tokenizer counts.** `scopedView` budgets whole record strings using four characters/token: 4,000 for local material minus NOW and reserved evidence; 300 for elsewhere footnotes. `recallScope` selects 16,000 local tokens with `deep`, and can suppress elsewhere (`src/scopes.ts:65`, `src/scopes.ts:118`, `src/scopes.ts:122`). Its `sinceMs` limits local episodes, not the atom-origin selection. Global view provides recent unscoped/active-project footnotes rather than arbitrary full global records (`src/scopes.ts:95`).
- **Free-text retrieval is a separate seam.** `queryIndex(index, queryText, opts)` combines lexical, entity and temporal signals; optional compatible vectors are additional inputs (`src/relindex.ts:687`, `src/relindex.ts:702`). Units already carry relative-path ID, source basename, content hash and full text (`src/relindex.ts:102`). `excerpt` creates a short first-sentence/claim excerpt, while `renderEvidenceBlock` retains source paths under an estimated budget (`src/relindex.ts:783`, `src/relindex.ts:800`). These are workable foundations for proposal 1's selection, expansion and disposable projections; they do not implement coherent multi-level abstraction.
- `retrieveForWake` is pure over a loaded index and declines stale/unanchored retrieval (`src/relindex.ts:903`). Wake uses it with a 1,000-token budget (`src/wake.ts:196`), then calls `recallScope` (`src/wake.ts:290`). Current payload excludes relational evidence for global/slim sessions (`src/wake.ts:300`). An optional view must explicitly choose its consumer; adding a renderer alone does not wire it into every lifecycle.
- `renderSelf(atoms, states, budgets, options)` returns Markdown plus address→atom manifest, filters active/pinned eligibility and renders open tensions separately (`src/render.ts:107`, `src/render.ts:117`, `src/render.ts:169`). This is a deterministic projection seam, not a general plugin interface.

## Existing reference shapes versus additions

- An `Atom` has `id`, one of four kinds, `claim`, `why`, quoted `{text, source}` pairs, episode stamps, optional `scope` (`src/atoms.ts:34`). ID is the first twelve SHA-256 hex characters of whitespace-normalized claim (`src/atoms.ts:98`): it is neither an episode identity nor a durable person identity.
- `LedgerEvent` already represents stack/decay/potentiate/supersede/renorm/contradiction/resolve/pin/forget; references include atom, source episode, winner/loser and unordered contradiction endpoints (`src/atoms.ts:46`, `src/atoms.ts:78`). `foldBeliefs` preserves explicit contradiction edges and handles their resolution (`src/atoms.ts:336`). Proposal 2 can use this as evidence of existing disagreement support; conditional compatibility, observer, validity period and unknown verdicts would be new semantics.
- Proposal 3 would need explicit predicates, endpoint roles and allowed composition rules. The existing relational index's entities and occurrence weights are lexical co-occurrence, not typed semantic relations (`src/relindex.ts:122`). Proposal 4's recipe inputs, binding/completion state, usefulness and retirement are new annotations/operations; the four atom kinds do not establish an executable recipe contract (`src/atoms.ts:34`).
- Proposal 5 can reference episode files and atoms, but n-ary event participation and interpretation-of links are new. Sleep records session provenance (harness/model/machine/session) independently of content and assigns a session-derived episode path (`src/sleep.ts:975`, `src/sleep.ts:1168`). This existing provenance is not an actor/participant ontology.
- Proposal 6 has concrete precedents: `quotesAreVerbatim` checks normalized substring presence, not semantic entailment (`src/stack.ts:353`); `assertRenderInvariant` compares a fresh disk-derived render with committed Markdown (`src/rem-popmem.ts:952`). New checks should name their exact property rather than claim general truth preservation.

## Lifecycle seams and publication

- GRAZE's `runWorker` writes scoped checkpoint bullets to a transient meal file (`src/graze.ts:312`, `src/graze.ts:390`). SLEEP's `draftSessionEpisode` includes meals, existing NOW/SELF and transcript in drafting, then publishes the episode/NOW and deletes the meal (`src/sleep.ts:983`, `src/sleep.ts:1070`, `src/sleep.ts:1181`, `src/sleep.ts:1210`). Supplemental capture could be designed alongside these boundaries; none of these functions accepts a plugin callback today.
- REM invokes `stackEpisode` for new episodes (`src/rem-popmem.ts:1250`); the stacker publishes atom files and ledger events (`src/stack.ts:1024`). Optional derivation from committed episodes is a narrower seam than replacing GRAZE/SLEEP. REM separately refreshes the relational index (`src/rem-popmem.ts:1643`). Supplemental storage will not enter retrieval automatically.
- `publish` accepts relative-path replacements and newline appends. Caller validates replacement content; built-in atom paths get strict atom validation (`src/publish.ts:10`, `src/publish.ts:49`). It uses a temporary Git index, builds from the current tip and compare-and-swaps the ref (`src/publish.ts:108`). Atom/proposed files are immutable once present; generic supplemental replacements do not inherit that rule (`src/publish.ts:112`). Publication provides durability, not semantic merge or deletion of arbitrary new object types.

## Forgetting and erasure constraints

- `changeAtom` accepts only an existing twelve-hex atom, appends pin/forget and re-renders SELF (`bin/circadian:39`). Forget makes ledger weight zero/status forgotten (`src/atoms.ts:410`); scope atom loading and SELF rendering filter it (`src/scopes.ts:110`, `src/render.ts:134`). It does not delete episode text or arbitrary supplemental objects.
- Index ingestion reads all episode/belief Markdown without folding the ledger (`src/relindex.ts:309`); `queryIndex` has no ledger-state input (`src/relindex.ts:702`). Thus a supplement must explicitly resolve current source availability/eligibility; it cannot assume every read surface already performs atom-forget filtering.
- `erase` rewrites reachable local Git history, removes the atom and matching ledger references, and redacts exact claim/why/quote strings; it requires clean attached local history and refuses any remote (`src/erase.ts:17`, `src/erase.ts:48`). It does not know arbitrary sidecar IDs or paraphrases. Referential cleanup and no-resurrection behavior must be designed for new data, without promising this atom-only command already covers it.

## Distinct CLI doors

Package `circadian` maps to `src/archaeology.ts`, offering when/bisect and dispatching erase/backfill/lane (`package.json:22`, `src/archaeology.ts:90`, `src/archaeology.ts:117`). The separate repository `bin/circadian` implements scope recall, status, pin and forget (`bin/circadian:30`, `bin/circadian:53`). Free-text index query is `bun src/relindex.ts --query …` (`src/relindex.ts:1013`). Do not document a proposed free-text recall or augmentation flag as existing today.
