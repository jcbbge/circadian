# All six proposals: peer-refined implementation, use and cases

**Current work: all six independent research prototypes are implemented with deterministic checks and outside peer code review.** These are optional augmentations to a working Circadian. That implementation phase included no production integration, behavioral inference evaluation or extension framework selection. The subsequent [Behavioral 005 assessment](../lab/behavioral-005/ASSESSMENT.md) now records a finite, separately frozen comparison across all six; it does not establish dependable integration benefit. The original conceptual dossiers and the six-topic design discussions remain the design history; these supplements now connect that history to executable research.

Each supplement specifies a useful operation, design-level inputs/outputs and algorithm, existing integration seams, disabled behavior, source/deletion obligations, applications, benefit measures, competent comparison arms, and literal cases with expected outcomes. **All 93 numbered case specifications are mapped: 92 have deterministic contract or boundary checks; R14's total-cost/usefulness comparison remains deferred.** These are case counts, not executed unit-test totals. Broader annotation fidelity, semantic preservation and practical benefit remain unvalidated. Behavioral 005 measures one reader consuming supplied evidence/annotations and actual operation outputs, with bounded Jev annotation choices; it does not measure automatic capture or full production behavior.

Use the [prototype entrypoint](../prototypes/README.md) for commands and demonstrations, [results manifest](../prototypes/results.json) for captured validation evidence, and [outside peer code review](../prototypes/PEER-REVIEW.md) for the preserved review of the initial implementations. The refinements below document the subsequent corrections and their limits.

## How these fit Circadian

The shared [source map](SOURCE-MAP.md) identifies actual record shapes, recall/rendering seams and capture/publication boundaries. Design-level API sketches are labeled as sketches and link to the actual local signatures. All six additions now run as small functions over supplied fixtures using the existing runtime. They add no third-party package, new database, universal ontology, theorem prover or always-on service.

01 fits selected recall/rendering. 02 and 03 produce contextual/relational reports over selected evidence. 04 adds optional reuse during relevant reasoning. 05 enriches access to committed episodes and later interpretations. 06 checks selected proposed changes. Optional derivation after committed episodes is available as a design seam; no proposal assumes a plugin callback already exists or requires changing the working SLEEP output contract.

Each works independently. The research runner can select individual demonstrations or none; empty selection imports/invokes no demonstration. This is not a production configuration interface. Shared source references permit combination later; there is no requirement to install all six, formalize every memory, select an identity system now or insert a mandatory startup classifier. Persistent additions still need their own explicit source-eligibility/deletion integration before live use.

The mathematical ideas retain concrete jobs: restriction and expansion; compatibility over overlapping contexts; typed composition and equations; substitution and specialization; incidence and shared boundaries; and checking selected preservation properties. Where ordinary code already implements the same operation, that is the minimal implementation—not a failed mathematical proposal. Full higher-category or proof-assistant machinery has not been selected.

## What changed through the peer discussion

- **Views:** coverage counts inside the same budget. Monotone growth is specified for a fixed prefix policy, not promised for arbitrary packing/reranking. Below the smallest representable response, rendering refuses the budget.
- **Compatibility:** unknown alignment remains separate from a known conflicting group. We did **not** adopt grouping by arbitrary connected overlaps: temporal overlap is not transitive. C15 supplies the counterexample.
- **Typed relations:** the peer withdrew its two-self-report preference threshold and naive join comparator. A reviewed alias is an explicit input; supported reports never become a timeless trait by count alone.
- **Operations:** specialization is stored as data for a known recipe. Instantiation takes explicit applicability and limits, writes no usage notes, and rejects conflicting bindings. Different bound-slot choices must reproduce the full result.
- **Experiences:** participation, simultaneity, interpretation authorship and question identity are distinct. A later outsider's reading may share an interpretation boundary without establishing attendance.
- **Transformations:** the peer accepted the missing-annotation correction and the limit on checking arbitrary prose. A receipt can record an old result but cannot validate changed or unavailable inputs. Retaining metadata after deletion depends on the deletion policy; it is not guaranteed merely because the receipt contains hashes.

A separate read-only case review caught underspecified fixture values, missing API limits/applicability, a weak negative equivalence example and ambiguous total-call accounting. Those were corrected in the supplements. Parent inspection accepted the design deliverables; empirical benefits remain hypotheses.

The later implementation review identified two concrete omissions, now corrected: contextual comparison must report an undeclared relevant record dimension as unknown, and selected-seed experience recall must account for relevant interpretations it did not reach. H05 now checks supplied same-boundary traversal and incomplete coverage, not lexical discovery. Presentation clarifications also distinguish unmet from total omitted view records, limit relation equations to query-matching reports, make place order part of an aid binding, and expose changed presentation bytes separately from represented-field differences and semantic checks.

## Experiment design and evidence

The [shared test protocol](TEST-PROTOCOL.md) separates current behavior, the same information with a competent simpler operation, and the proposed operation. It separates structural validity, annotation fidelity and downstream usefulness. Each proposal nominates two positive and two challenge cases for a future dedicated run.

The implemented phase exercises reviewed fictional inputs, deterministic operations, dedicated case maps and runnable demonstrations. Simpler operation equivalence is preserved where appropriate. It makes no model calls and does not claim measured superiority over Circadian or over those simpler operations. Exact executed test counts and source hashes belong in the linked results manifest rather than this design inventory.

The earlier proposed first comparison was 24 trials per selected proposal/model, with at most one follow-up model call each: **48 reader calls maximum**. That design was not executed as written. The subsequent [Behavioral 005 protocol](../lab/behavioral-005/PROTOCOL.md) instead froze four cases for each of all six proposals and three conditions. Any new study must independently fix its model/provider/settings and fixture versions. Start without Jev; any applicable Jev selector/extraction comparison is a separate bounded arm, with its complete cost reported. Deterministic core functions do not need a classifier.
